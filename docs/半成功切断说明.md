# 半成功切断说明

> 锁定日期：2026-11-20。**当天禁止改口**；偏离本说明的写路径一律拒写，并记 `半成功偏了`。

## 缺陷形态

重映回执成功后，正式区出现新键，但入站旧键行未清除，冲突区无对应挂起；
入站列表与互证卡各报一数（半成功撕裂）。

## 选定口径：乙路径（同库一次事务，同败同成）

重映统一沿用既有入口 `POST /api/remap`，不另开缺陷台、不新增旁路写接口。

1. 每次重映以 `BEGIN IMMEDIATE` 开启**同库写事务**，先取库级写锁。
2. 事务内依次完成：
   1. 占锁后重读入站行 `inbound_queue`：行状态已为 `已重映` → 只写一条
      `remap_audits(outcome='争用')` 留痕并提交该留痕，回执 409，正式区零增、
      入站不动、冲突区不挂起（后到只记争用）；行不存在则同事务先登记为
      `待重映`（首次入站），再进入映射判定，不得把首次入站误判为争用。
   2. 查生效版本与映射：无映射 → 写冲突区挂起与审计留痕后提交，正式区零增、入站不动。
   3. 入站清除（`UPDATE inbound_queue SET status='已重映'`，校验影响行数恰为 1）
      与正式插入（`INSERT formal_entities`）及成功审计**在同一事务内提交**。
3. 任一步失败：`ROLLBACK`，正式区零增、入站行保持 `待重映`，回到撕裂前状态；
   回滚后另起短事务记 `remap_audits(outcome='回滚')`，仅留痕，不改五处视图数据。
3.1 偏离本说明的写路径（如入站清除影响行数不为 1，无法与正式插入配对）：
   抛 `HalfSuccessDeviation` 拒写，两侧回滚，另起短事务记
   `remap_audits(outcome='半成功偏了')`，回执 500 并明示"半成功偏了"。
4. 禁止甲路径写法（提交前预校失败即拒绝、靠校验代替事务）：预校与写入之间存在
   TOCTOU 窗口，且无法覆盖双路抢映。**甲乙两边不得混用**：不得在事务外先做
   "先删后插"、不得只靠展示过滤掩盖撕裂。
5. 禁止只改刷新按钮或任何前端文案；展示层只允许如实呈现后端同事务结果。

## 五处对齐口径

正式区、入站列表、冲突区、互证卡、重映回执五处禁止撕裂：

- 互证卡 `/api/reconciliation` 由库内同批数据派生：
  - `torn` = 正式区 `mapped_from` 中入站仍为 `待重映` 的旧键，必须为空；
  - `orphan_cleared` = 入站已清除但正式区无对应行的旧键，必须为空；
  - `aligned` 仅在两者皆空时为真。
- 重映回执携带 `old_key / entity_key / outcome / audit_id`，与库内审计行一致。

## 争用锁

两路同时重映同一旧键：`BEGIN IMMEDIATE` 保证同库串行，先到者同事务完成
清除+插入，后到者占锁后重读发现行已被清除，只记争用留痕，回执 409，
不得产生第二条正式区行、不得重复清除、不得在冲突区挂起。
